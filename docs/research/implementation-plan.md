## P2 — 数据集建设与冻结

1. 对 1,100 条标签记录重新做结构、格式和哈希审计。
2. 按来源分层建立固定 880/220 训练/验证划分。
3. 从 287 张未引用图片中按固定种子抽取 200 张。
4. 提供本地离线人工标注工具，隐藏所有模型预测。
5. 由维护者亲自校对 200 张图片；不可辨认样本从剩余 87 张补抽。
6. 冻结标签、抽样清单、图片哈希和数据版本。
7. 将剩余 87 张保留为独立无标签数据。

P2 不运行模型 Benchmark，不根据 OCR 预测修改人工标签。

## P3 — PyTorch 训练重建

1. 从历史 emtl 推理实现和模型元数据确认 Baseline 网络结构。
2. 明确记录新训练超参数和随机种子。
3. 训练最多三个模型：Baseline、更小 CNN、有限通道调整 CNN。
4. 使用相同 880/220 数据划分。
5. 保存配置、训练日志、每轮指标、Checkpoint 和环境版本。
6. 仅使用内部验证集选择模型。
7. 根据“准确率差不超过 1 个百分点时优先选更小模型”的规则冻结一个模型。

新实验明确标记为 reconstructed experiment，不伪称历史复现。

## P4 — 推理与离线 Benchmark

1. 提供独立纯 Python + Pillow 推理实现。
2. 与 PyTorch 参考推理比较输出一致性。
3. 冻结最终模型、代码版本、依赖版本及 200 张标签。
4. 分别在 ddddOCR 1.4.11 和 1.6.1 的隔离环境运行。
5. 保存逐张预测和汇总指标。
6. 报告整图准确率、字符准确率和前导零识别率。
7. 90% 目标未通过时照实报告，不使用同一盲测集继续调参。

## P5 — 开源交付与独立 Review

- 检查代码、数据、标签、模型权重及文档许可证。
- 检查第三方字体来源不确定性披露。
- 检查数据、标签和模型哈希清单。
- 验证新环境从数据准备到推理评估的复现流程。
- 完成文档、示例和离线测试。
- 由独立 Review 检查实验设计、数据泄漏、指标和授权边界。
- 创建最终交付 PR；是否合并、打 Tag 或发布由维护者另行批准。

## 分支与 PR 规则

- 所有修改从最新 `main` 创建独立工作分支。
- 分支按阶段命名，例如 `docs/p1-research-foundation`、`data/p2-dataset-freeze`、`train/p3-cnn-reconstruction`。
- 不直接向 `main` 推送提交。
- 每阶段 PR 明确列出范围、证据、测试和未解决风险。
- 创建 PR 不代表获得合并授权。
- 不自动合并，不自动创建发布 Tag，不自动发布 PyPI。
