# 研究需求与验收约束

**版本：** v1.0  
**状态：** 已批准  
**范围：** emtl-OCR 第一阶段

## 1. 项目目标

建设一个完全独立于 `emtl` 的研究型 OCR 仓库，公开并尽可能复现此前针对四位数字本地图像的研究成果，包括数据、人工标注、训练方法、模型结构、推理实现和 ddddOCR 对比。

第一阶段不发布 PyPI 包，不修改 `emtl`，不开发在线 OCR 服务，也不实现远程验证码采集、登录或认证接口调用。

## 2. 交付范围

1. 数据集、人工标签、数据来源说明、固定划分和 SHA-256 清单。
2. 数据审计、人工标注及数据预处理工具。
3. PyTorch 训练代码、实验配置、随机种子、训练日志和检查点。
4. 最终模型权重及独立推理实现。
5. 纯 Python + Pillow 推理运行时，不依赖 PyTorch、NumPy 或 ONNX Runtime。
6. ddddOCR 1.4.11 和 1.6.1 的隔离环境 Benchmark。
7. 逐张预测结果、汇总指标、研究报告及复现文档。
8. 失败实验和重要方案淘汰依据。

## 3. 数据范围与划分

### 3.1 已恢复的 1,100 条有标签记录

按来源字段分层：

| 来源 | 训练集 | 内部验证集 | 合计 |
|---|---:|---:|---:|
| ACCEPTED | 800 | 200 | 1,000 |
| REJECTED | 24 | 6 | 30 |
| SKIPPED_INVALID_FORMAT | 56 | 14 | 70 |
| **合计** | **880** | **220** | **1,100** |

来源字段表示样本进入标注集前的采集/筛选类别，不是模型输出类别。标签目标是四位数字字符串，必须保留前导零。

重新生成固定随机种子的数据划分文件。三个候选模型使用完全相同的 880/220 划分。

### 3.2 新的 200 张盲测集

从归档中 287 张未被训练清单引用的图片中，固定随机抽取 200 张，由项目维护者亲自标注。其余 87 张保留为无标签备用图片。

约束：

- 抽样种子、图片路径和 SHA-256 必须写入清单。
- 标注界面不显示任何 OCR 预测。
- 每个标签必须是四位数字字符串，保留前导零。
- 无法辨认的图片记录跳过原因，并按预先记录的抽样顺序从备用图片补足。
- 标签冻结后才允许运行任何 Benchmark。
- 200 张盲测图片不得参与架构选择、训练、超参数调整或数据增强设计。

历史 100 张验收图片原件目前缺失。其历史标签和预测记录只用于历史报告，不代替新盲测集。

### 3.3 排除范围

最初 20 张来自远程服务的探索图片不公开、不进入正式数据集。可以在历史研究记录中保留非图片形式的实验结论和来源说明。

## 4. 训练实验

最多比较三个模型，包含历史 tiny-CNN Baseline：

- Model A：恢复历史模型结构的重建基线。
- Model B：更小的 CNN。
- Model C：有限调整通道数或卷积结构的 CNN。

原始训练脚本、完整配置和检查点尚未恢复。新实验必须标记为 reconstructed experiment，不得声称是历史训练的精确复现。

### 4.1 数据增强

只对训练集使用有限增强：

- 轻微亮度与对比度变化。
- 少量像素噪声。
- 水平和垂直方向最多 1 像素平移。
- 不使用旋转、裁剪、字符变形或随机擦除。

验证集和盲测集不做增强。增强范围、概率、随机种子必须记录。

### 4.2 模型选择规则

首先比较内部验证集整图准确率。若较小模型与最高准确率模型相差不超过 1 个百分点，则选择较小模型；其后再比较模型体积和推理耗时。

不增加第四个候选模型，不以盲测结果选择模型。

## 5. Benchmark

同一批 200 张冻结盲测图片分别交给：

1. 最终冻结的 tiny-CNN。
2. ddddOCR 1.4.11。
3. ddddOCR 1.6.1。

两个 ddddOCR 版本使用独立虚拟环境，并记录准确的 Python、包版本及运行配置。所有引擎使用相同图片和相同人工标签。

报告指标：

- 整图准确率：完整四位数字全部正确的样本数 / 200。
- 字符准确率：按字符编辑距离统计，并单独说明长度不匹配的处理。
- 前导零识别率：真实标签以 0 开头的样本中，完整识别正确的比例。
- 每张图片的原始预测、错误类别及运行状态。

不得通过删除错误样本、去除前导零或按模型选择性预处理来提高准确率。

## 6. 验收标准

- 正式盲测整图准确率目标：至少 180/200（90%）。
- 推理只依赖 Pillow + Python 标准库。
- 训练和推理代码独立于 emtl。
- 数据划分、模型配置、模型文件及逐张预测可审计。
- 三个引擎在相同 200 张盲测图片上完成比较。
- 完整记录模型、数据和软件版本。

90% 是目标门槛，不是发布前修改数据或隐藏失败结果的理由。若未达到，照实报告 FAIL，不对这批盲测数据继续调参。

推理延迟和部署体积可以记录，但不设硬性门槛。

## 8. 阶段边界

- P0：恢复历史证据并完成数据完整性审计。
- P1：需求、研究记录、实施计划、许可证说明和工程规范。
- P2：建立固定数据集划分、200 张人工盲测标签和数据冻结。
- P3：最多三个模型的重建训练实验。
- P4：冻结模型、纯 Python 推理及三引擎盲测。
- P5：开源交付、独立 Review 和发布审查。
