# 研究需求与验收约束

**版本：** v1.0  
**状态：** 已批准  
**范围：** emtl-OCR 第一阶段

## 1. 项目目标

建设一个完全独立于 `emtl` 的研究型 OCR 仓库，公开并尽可能复现此前针对四位数字本地图像的研究成果，包括数据、人工标注、训练方法、模型结构、推理实现和 ddddOCR 对比。

第一阶段不发布 PyPI 包，不修改 `emtl`，不开发在线 OCR 服务，也不实现远程验证码采集、登录或认证接口调用。

## 2. 交付范围

1. 数据集、人工标签、数据来源说明、固定划分和 SHA-256 清单。
2. 数据审计、人工标注及数据预处理工具。
3. PyTorch 训练代码、实验配置、随机种子、训练日志和检查点。
4. 最终模型权重及独立推理实现。
5. 纯 Python + Pillow 推理运行时，不依赖 PyTorch、NumPy 或 ONNX Runtime。
6. ddddOCR 1.4.11 和 1.6.1 的隔离环境 Benchmark。
7. 逐张预测结果、汇总指标、研究报告及复现文档。
8. 失败实验和重要方案淘汰依据。

## 3. 数据范围与划分

### 3.1 已恢复的 1,100 条有标签记录

原始 1,100 张有标签图片固定划分为：

| Split | 图片数 |
|---|---:|
| train | 880 |
| validation | 220 |
| **合计** | **1,100** |

历史划分过程使用来源分层 80/20 方法和固定随机种子 `20261127`。来源分类和样本 ID 不进入公开数据集。由于来源分类不公开，公开 seed 和方法说明不能单独重建原始分层结果；公开 Manifest 中的实际成员关系是唯一权威依据。

标签目标是四位数字字符串，必须保留前导零。

### 3.2 200 张公开固定测试集

从原始归档中未被 1,100 条标签清单引用的候选图片中，最终选出并人工标注 200 张，作为公开固定测试集。其余 87 张候选图片不公开。

约束：

- 图片路径和 SHA-256 必须写入清单。
- 标注界面不显示任何 OCR 预测。
- 每个标签必须是四位数字字符串，保留前导零。
- 无法辨认的图片记录跳过，并按预先确定的候选顺序从备用图片补足。
- 测试集成员关系固定，不得转入训练集或验证集。
- 测试图片和标签已经公开，因此不再是保密盲测集。
- 测试集不得参与架构选择、训练、超参数调整或数据增强设计；模型冻结后才进行正式评估。

历史 100 张验收图片原件目前缺失。其历史标签和预测记录只用于历史报告，不代替新的公开固定测试集。

### 3.3 排除范围

最初 20 张来自远程服务的探索图片不公开、不进入正式数据集。可以在历史研究记录中保留非图片形式的实验结论和来源说明。

## 4. 训练实验

最多比较三个模型，包含历史 tiny-CNN Baseline。原始训练脚本、完整配置和检查点尚未恢复；新实验必须标记为 reconstructed experiment，不得声称是历史训练的精确复现。

### 4.1 候选模型

三个模型统一输入 64×24 RGB，三层 3×3、stride-2、padding-1 卷积，ReLU；FC1 使用 ReLU，FC2 输出 40 个 Logits 并 reshape 为 4×10。卷积层和全连接层均启用 Bias；不使用 BatchNorm、Dropout；三个模型全部随机初始化，不加载历史冻结权重。

| 模型 | 卷积通道 | FC1 | 参数量 |
|---|---|---:|---:|
| A | 3→8→16→24 | 128 | 83,888 |
| B | 3→6→12→16 | 64 | 29,812 |
| C | 3→8→16→32 | 96 | 83,736 |

Model A 的历史推理源码注释声称参数量为 83,984；按实际层维度计算为 83,888。P3 以实际结构和 PyTorch 参数计数为准，并保留该历史记录差异。

### 4.2 固定训练配置

- 最大 100 Epoch；连续 15 Epoch 未提升 Validation 整图准确率则停止。
- Batch Size 64；drop_last=False；num_workers=0。
- AdamW，Learning Rate 0.001，Weight Decay 0.0001；不使用 Scheduler 或 Label Smoothing。
- Loss 为四个数字位置的 Cross Entropy 平均值。
- CPU 单线程：PyTorch intra-op / inter-op 均为 1；启用 deterministic algorithms。
- Python、NumPy、PyTorch 随机状态固定。
- 三个随机种子：20261127、20261128、20261129。
- 每个 seed 下 A/B/C 使用相同 Epoch Shuffle、Batch 划分和逐图片增强序列；增强随机状态按 seed、epoch、image_id 派生，不受模型初始化的随机数消耗影响。

### 4.3 数据预处理与增强

所有图片转换为 RGB，使用 BILINEAR Resize 到 64×24；反色归一化为 (255 - pixel) / 255.0。

仅训练集增强，按以下顺序执行：

1. Brightness：独立概率 50%，倍率均匀采样 0.9～1.1。
2. Contrast：独立概率 50%，倍率均匀采样 0.9～1.1。
3. 反色归一化。
4. Gaussian Noise：概率 30%，σ 均匀采样 0～0.02，RGB 通道独立采样，裁剪到 [0,1]。
5. Translation：概率 50%，水平、垂直偏移分别从 -1、0、1 采样，归一化空间越界填 0。

不使用旋转、裁剪、字符变形或随机擦除。Validation 不做随机增强。

### 4.4 Checkpoint 与模型选择

- Checkpoint 首先按 Validation 整图准确率选择；准确率相同时选择 Validation Loss 较低者。
- Early Stopping 只根据 Validation 整图准确率改善重置 Patience；Loss 下降不重置 Patience。
- Ubuntu x86_64 正式训练 9 次；Intel Mac x86_64 跨平台复现验证也完整训练 9 次。
- 每个平台各训练 A/B/C × 三个随机种子，共 9 次；两个平台合计 18 次。
- 报告每个模型三次 Validation 整图准确率的均值和样本标准差。
- 模型架构按三次平均 Validation 准确率选择；若较小模型与最高平均值相差不超过 1 个百分点，选择参数量较少者。
- 在胜出架构的三个 Seed 中选择 Validation 准确率中位数对应的 Checkpoint；准确率并列时选择 Validation Loss 较低者。
- Mac 与 Ubuntu 按模型、Seed 配对比较，Validation 整图准确率差异须不超过 1 个百分点；超出时调查原因，不直接判定通过。
- 不以公开固定 Test 集进行训练、架构选择、超参数调整或 P3 验收。

### 4.5 环境与产物

使用 conda-forge：Python 3.12、PyTorch 2.14.1 CPU Generic、NumPy 2.3.3、Pillow 13.0.0。正式环境为 Ubuntu x86_64，Intel Mac x86_64（macOS 12.0+）作为复现环境。两个平台不使用 CUDA、MPS 或 MKL。

每次训练保存最佳 Checkpoint、逐 Epoch Training/Validation Loss 与整图准确率、Learning Rate、Epoch 耗时、实际配置、软硬件环境、运行状态及 Checkpoint SHA-256。训练产物保存在本地 outputs/，不提交公开数据集仓库。

## 5. Benchmark

同一批 200 张公开固定测试图片分别交给：

1. 最终冻结的 tiny-CNN。
2. ddddOCR 1.4.11。
3. ddddOCR 1.6.1。

两个 ddddOCR 版本使用独立虚拟环境，并记录准确的 Python、包版本及运行配置。所有引擎使用相同图片和相同人工标签。

报告指标：

- 整图准确率：完整四位数字全部正确的样本数 / 200。
- 字符准确率：按字符编辑距离统计，并单独说明长度不匹配的处理。
- 前导零识别率：真实标签以 0 开头的样本中，完整识别正确的比例。
- 每张图片的原始预测、错误类别及运行状态。

不得通过删除错误样本、去除前导零或按模型选择性预处理来提高准确率。

测试集标签公开后，必须将其称为公开固定测试集，不得宣称其仍是保密盲测集。

## 6. 验收标准

- 正式测试整图准确率目标：至少 180/200（90%）。
- 推理只依赖 Pillow + Python 标准库。
- 训练和推理代码独立于 emtl。
- 数据划分、模型配置、模型文件及逐张预测可审计。
- 三个引擎在相同 200 张测试图片上完成比较。
- 完整记录模型、数据和软件版本。

90% 是目标门槛，不是发布前修改数据或隐藏失败结果的理由。若未达到，照实报告 FAIL，不对这批测试数据继续调参。

推理延迟和部署体积可以记录，但不设硬性门槛。
