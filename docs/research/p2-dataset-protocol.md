## 2. 测试图片抽样和人工标注

原始归档中有 287 张图片未被原始 1,100 条标签清单引用。按固定随机种子和预先生成的候选清单，先抽取 200 张作为候选测试集，其余 87 张作为备用。

人工标注约束：

- 使用本地 Web 页面，只显示原始图片。
- 不显示或请求任何 OCR 预测。
- 输入必须是恰好四位 ASCII 数字字符串，保留前导零。
- 支持跳过、断点续标和重新标注。
- 每次提交或跳过均追加 JSONL 事件，不覆盖历史。
- 每张图片以最后一次事件决定最终状态。
- 跳过图片由备用候选补足，直到获得 200 条唯一有效标签。

最终结果：200 条有效标签、5 张最终跳过图片、206 条操作事件。200 张最终有效测试图片由 195 张首选候选图片和 5 张备用图片组成。剩余 87 张候选图片（5 张跳过、82 张未使用备用）不公开。

```text

```

| Split | 图片数 |
|---|---:|

不公开原始来源分类、`sample_id`、原始标签 CSV、标注操作历史、私有冻结文件、87 张未公开候选图片和最初 20 张远程来源探索图片。

## 5. Public Fixed Test Set 使用规则

由于测试图片和人工标签现在均公开，准确术语为 **Public Fixed Test Set**，不再称为保密盲测集。

其 200 张成员关系固定：

- 不得加入训练集或验证集。
- 不得新增测试图片。
- 不得删除或移动现有测试图片。
- 模型冻结前不查看测试集评估结果。
- 不使用测试集进行训练、架构选择、超参数调整或数据增强设计。
- 模型冻结后运行一次正式评估，如实报告结果。
- 若测试标签确有错误，允许修正，但必须在 Git Commit 中保留前后差异、修正原因并更新审计记录；历史评估结果应注明使用的标签状态。

新增图片只允许加入训练集或验证集。原有 880/220/200 基线成员关系不得改变。

## 6. 自动化构建和审计

首次构建：

```bash
python tools/build_public_dataset.py \
  --archive /path/to/captcha_train_1100.tgz \
  --blind-labels /path/to/blind-test-labels.csv \
  --blind-progress /path/to/blind-test-progress.jsonl \
  --blind-freeze /path/to/blind-test-freeze.json \
  --output datasets
```

完整审计：

```bash
python tools/audit_dataset.py \
  --dataset datasets \
  --verify-images \
  --verify-labels \
  --verify-splits
```

构建工具拒绝覆盖已存在的数据集目录。后续标签修正直接修改 `datasets/labels.csv`；`labels.csv` 是唯一权威标签源。重建图片或审计时不得覆盖人工修正过的标签。
